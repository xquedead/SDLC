# ADR-0005: Реализация аналитической сводки тура (Markdown/CSV) и быстрого меню трея поверх локального кэша SQLite

## Контекст и постановка задачи

Во втором раунде обсуждения с Заказчиком (`plan/correspondence.md`, письмо 5) состав функционала релиза `1.0` был изменён: отдельная вкладка детальной статистики команды за 10 прошлых и 5 будущих матчей (`REQ-FUNC-007` / `SYS-F-08`) исключена из релиза `1.0`, но добавлен новый модуль **`SYS-F-13: Blogger digest (MD/CSV) & tray LIVE menu`** (`REQ-FUNC-015`).

Для спортивного блогера (`BG-3`) требуется формирование готовой сводки текущего тура с выгрузкой в Markdown (`.md`) и CSV (`.csv`), а для болельщика (`BG-1`, `BG-2`) — быстрый просмотр сегодняшних и идущих сейчас (`LIVE`) матчей прямо из контекстного меню иконки в системном трее Windows без разворачивания главного окна. При этом действует жёсткое ограничение бесплатного тарифа `football-data.org` (`<= 10 запросов/мин`, `C-3`) и жёсткий срок релиза `18.12.2026`.

Необходимо определить архитектурный способ получения данных для `BloggerReportExporter` и `TrayNotifier` без дополнительной нагрузки на внешний REST API и с возможностью делегирования части задачи `junior`-разработчику.

## Драйверы решения

* Ограничение квоты внешнего API (`C-3`, `REQ-FUNC-012`): новые функции не должны создавать дополнительных HTTP-запросов сверх регулярного фонового обновления.
* Жёсткий срок релиза `18.12.2026`: необходимость чёткого разделения модуля на ядро агрегации (Middle) и генерацию текстовых шаблонов `.md`/`.csv` (Junior).
* Автономная работа (`BG-4`, `REQ-AVAIL-001`): экспорт сводки тура должен работать и без сети по данным локального кэша.
* Нулевой бюджет (`SRS 3.5.7`): запрет на подключение платных сторонних библиотек генерации отчётов.

## Рассмотренные варианты

* **Вариант 1:** Модуль `BloggerReportExporter` читает данные исключительно из локального репозитория `ICacheRepository` (`SQLite cache.db`) и формирует чистые текстовые файлы `.md` (таблицы GFM) и `.csv` (`UTF-8 with BOM`) средствами стандартного C++17 / Qt Core; контекстное меню трея `QMenu` в `TrayNotifier` также читает кэшированные матчи на текущие сутки (`LIVE` / `SCHEDULED`).
* **Вариант 2:** Выполнение отдельных прямых HTTPS-запросов к `football-data.org` при каждом открытии меню трея или нажатии кнопки «Сформировать сводку».
* **Вариант 3:** Генерация отчётов в форматах `.docx` или `.pdf` с подключением тяжёлых внешних библиотек.

## Итог решения

Выбранный вариант: **«Вариант 1: Чтение данных только из `ICacheRepository` (SQLite) и генерация лёгких текстовых форматов Markdown и CSV средствами стандартной библиотеки»**, потому что он гарантирует **нулевую дополнительную нагрузку** на лимит 10 запросов/мин (`C-3`), работает в офлайн-режиме (`BG-4`) и позволяет полностью отделить генератор форматов (`T-13.2`) как изолированную задачу для `junior`-разработчика в Итерации 4.

### Последствия

* Хорошо, потому что сводка тура и список сегодняшних матчей в трее открываются мгновенно (`< 50 мс`) даже без подключения к интернету.
* Хорошо, потому что формат CSV с `UTF-8 BOM` без искажения кириллицы открывается в Microsoft Excel, а Markdown сразу вставляется в публикации блогера.
* Плохо, потому что актуальность статуса `LIVE` в меню трея ограничена интервалом фонового обновления (10 минут, `REQ-FUNC-012`), о чём пользователю выводится метка времени последнего обновления.

### Подтверждение

1. Инспекция кода: класс `BloggerReportExporter` зависит только от `ICacheRepository` и не имеет доступа к `IFootballApiClient`.
2. Модульные тесты `T-13.2` и `T-13.3`: проверка корректного экранирования кавычек/разделителей в `.csv`, валидности таблиц Markdown и отображения матчей на текущую дату в меню `TrayNotifier`.

## Плюсы и минусы вариантов

### Вариант 1: Чтение из `ICacheRepository` + генерация Markdown / CSV

* Хорошо, потому что не расходует квоту 10 запросов/мин и не требует сторонних библиотек.
* Хорошо, потому что идеально декомпозируется между ведущим и младшим разработчиками.
* Нейтрально, потому что обновляется с шагом 10 минут (либо вручную по `F5`).

### Вариант 2: Прямые запросы к API при открытии меню трея

* Хорошо, потому что показывает счёт на секунду клика.
* Плохо, потому что при частых кликах мгновенно приводит к `HTTP 429` (`C-3`) и не работает без сети (`BG-4`).

### Вариант 3: Генерация `.docx` / `.pdf`

* Хорошо, потому что даёт готовый печатный документ.
* Плохо, потому что увеличивает трудоёмкость в 2–3 раза и срывает срок релиза `18.12.2026`.
